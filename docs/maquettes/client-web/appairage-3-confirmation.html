Pour la session de code

  • La clé d'accès (WebAuthn, vérification de l'utilisateur obligatoire) est demandée par le système, pas par la page. La feuille prépare le geste et le bouton lance navigator.credentials.get. Aucun mot de passe de repli.
  • Le résumé montre le nom et le rôle choisis à l'étape 1, pour que le propriétaire confirme ce qu'il a réellement demandé et pas seulement qu'un code a été saisi.
  • Le cookie __Host-session est posé par le serveur. L'interface ne montre aucun jeton ni identifiant.
  • La planche 3c traduit la règle de la conception : un deuxième navigateur qui tente un code ferme l'association et alerte le propriétaire. Texte volontairement sobre pour ne pas affoler.
  • Dans la feuille, l'action destructrice (Refuser) est un lien, l'action de confiance est le bouton plein. Le focus initial va sur le bouton principal.
